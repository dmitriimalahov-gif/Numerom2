# Мобильное обучение: клиент пилота

## Реализованное поведение

Список показывает серверный `progress_data` каждого урока и обновляется при возвращении из урока; дополнительных запросов прогресса на каждую строку нет.

Экран `/lesson/[id]` загружает активный урок через общий авторизованный клиент. Смена пользователя или урока создаёт новое состояние экрана. После 401 действует общий механизм выхода, основной токен не передаётся внешним приложениям.

- Теория отображается как текст: поддержаны `lesson.theory`, поля `content.theory`, пользовательские блоки и скрытые преподавателем поля. Скрипты/стили из разметки удаляются. Для урока без текстовой теории и с прикреплёнными файлами доступна отметка «Материалы изучены». Отметка «Теория прочитана» отправляется отдельным действием и подтверждается серверным прогрессом.
- После подтверждённой отправки теста, упражнения или отметки чтения обновляются серверный прогресс и общий профиль/баланс сессии. Сбой обновления баланса не отменяет сохранённый результат: для баланса показан отдельный повтор.
- В прогрессе показаны только серверные значения. Отсутствующий/некорректный ответ становится ошибкой с повтором, а не нулём или локально вычисленным завершением.
- Упражнения поддерживают текст и выбор опубликованного варианта. Сохранённый ответ, непереданные изменения, ожидание проверки и комментарий преподавателя различаются. Наличие локального текста не означает сохранение или положительную оценку.
- Тест проходится по вопросам с навигацией назад. В запросе — только реальные ответы, ID урока/теста и UUID попытки; приложение не вычисляет оценку, прохождение или награду. Результат появляется только после корректного ответа сервера. История подгружается отдельно.
- Сетевой сбой/неполный ответ сохраняет UUID и неизменный снимок ответов до повтора: повтор не создаёт новую попытку. Явный 4xx-отказ, кроме конфликта идентификатора, позволяет исправить ответы. Защита от двух быстрых нажатий действует синхронно, до обновления интерфейса.
- Список материалов берётся из серверного списка файлов урока. При нажатии запрашивается короткоживущая ссылка на конкретный файл. PDF, изображения, аудио/видео или скачиваемый документ открывает браузер/приложение устройства. В ссылке нет основного токена сессии. Поддержана опубликованная HTTPS `video_url`, если сервер её предоставляет. Для Bunny запрашивается новый авторизованный маршрут `/student/lesson-video/{lesson_id}/access`; закрытый старый маршрут не вызывается. Отсутствие настройки видео возвращается пользователю как ошибка без ложного успешного просмотра.
- Прогресс, материалы, сохранённые ответы и история теста имеют отдельные ошибки и повтор. Уже введённый ответ сохраняется при обновлении других разделов.

Встроенная озвучка: отдельные записи у блока теории, упражнения и вопроса теста; введение и задания по дням собраны в аудиоверсию внизу урока. Запуск по нажатию, пауза и возврат к началу. Готовность записей обновляется автоматически без прерывания проигрывания. Прослушивание не меняет прогресс. Тексты и доступ: [project-narration.md](project-narration.md).

## Используемые контракты

Пути ниже дополняются `/api` общим клиентом. Все JSON-запросы используют текущий Bearer из общей сессии.

| Метод | Путь | Тело/ответ |
| --- | --- | --- |
| GET | `/learning-v2/lessons` | `{lessons:[{...,progress_data}],user_level}` |
| GET | `/learning-v2/lessons/{lesson_id}` | `{lesson,progress}`; прогресс экрана читается отдельно |
| GET | `/student/lesson-progress/{lesson_id}` | `completion_percentage,is_completed,theory_read,exercises_completed,quiz_passed` |
| POST | `/student/lesson-progress/{lesson_id}/theory` | `{}` → подтверждённый прогресс |
| GET | `/student/exercise-responses/{lesson_id}` | `{exercise_responses:{exercise_id:{id,response_text,reviewed,admin_comment,submitted_at}}}` |
| POST | `/student/exercise-response` | `{lesson_id,exercise_id,response_text}` → `{response_id}` |
| GET | `/student/quiz-attempts/{lesson_id}` | `{attempts:[{id,score,passed,attempted_at,submission_id}]}` |
| POST | `/student/quiz-attempt` | `{lesson_id,quiz_id,answers:{question_id:string},submission_id}` → `{attempt_id,score,passed}` |
| GET | `/student/lesson-files/{lesson_id}` | `{files:[{id,original_name,mime_type,file_size,extension,section}]}` |
| GET | `/student/lesson-files/{lesson_id}/{file_id}/access` | `{url}`; запускается только по нажатию |
| GET | `/student/lesson-video/{lesson_id}/access` | Bunny: `{url,expires_in}`; запускается только по нажатию |
| GET | `/narration/lesson/{lesson_id}` | Видимые тексты, статус и короткие ссылки готовых записей |
| POST | `/narration/lesson/{lesson_id}/{clip_id}/access` | `{}` → ссылка или статус подготовки существующего фрагмента |
| GET/HEAD | `/student/narration-media/{token}` | Защищённый аудиопоток, поддерживает Range |

Ссылка файла должна иметь HTTPS. `javascript:`, `data:`, `file:`, относительные/HTTP-адреса и URL с логином/паролем не открываются. Клиент не использует старый `/download-file`, не отправляет статистику просмотра или выдуманные минуты.

## Границы

Для публичного пилота нужны новые проверенные `student_learning` и `student_media` маршруты и соответствующий gateway. Старый сервер, принимавший оценку/баллы от клиента, несовместим с отправкой теста. Сервер обязан проверять доступ к активному уроку, принадлежность упражнения/файла и повтор UUID.

Bunny-видео требует настройки защищённого embed на сервере. Реальный Bunny-видеопоток в этой задаче не проверялся; старый небезопасный маршрут закрыт gateway и не используется клиентом.

Приложение не воспроизводит видео внутри собственного экрана и не начисляет время просмотра. Внешний просмотр/скачивание зависит от браузера и доступных на устройстве приложений. Срок ссылки ограничен сервером: после истечения материал открывается повторным нажатием.

Челленджи по дням пока остаются на сайте и могут быть необходимы для 100% прогресса. Редкие типы вопросов, загрузка файла как ответа и HTML-виджеты не подменяются упрощённым успешным прохождением: неподдерживаемый тест отмечается как требующий обновления. Черновики ответов и неподтверждённая попытка хранятся только в памяти открытого экрана, не переживают закрытие приложения; серверная история остаётся источником сохранённых результатов.

## Проверка

`mobile/test/learning.test.js` проверяет реальные ограничения payload, отсутствие клиентских оценок, варианты и размеры ответов, недопустимые URL, подтверждение результата, сохранённые статусы, двойное нажатие и повтор того же UUID/ответов после потерянного ответа сервера. Проверка типов: `npm run typecheck` из `mobile`.

Проверки контрактов и TypeScript не доказывают работу production-сервера, системного PDF/видеоплеера или реального телефона. Совместную сборку и визуальное испытание выполняет основной поток после интеграции серверных изменений. Зависимости и SDK в этой задаче не изменены.
