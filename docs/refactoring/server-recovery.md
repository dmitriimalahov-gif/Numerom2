# Восстановление NumerOM после сбоя

Настройка перенесена по рабочему принципу Helper: launchd перезапускает службы, сторож проверяет доступность, приложение получает подписанный адрес API с постоянного адреса GitHub Pages.

## Для пользователя

Ссылка остаётся прежней: https://dmitriimalahov-gif.github.io/numerom-app/

После первого обновления страницы новая версия сама проверяет адрес сервера при запуске, возвращении в приложение, появлении интернета и раз в 30 секунд. Если сервер временно недоступен, действующий вход сохраняется. После восстановления связи приложение повторяет восстановление сеанса. Истёкший или отозванный вход требует обычной авторизации.

Компьютер должен быть включён, подключён к интернету, а пользователь macOS — войти в систему. Служба caffeinate предотвращает обычный сон по бездействию, но не отключение питания и не закрытие крышки. Пока сервер выключен, новые расчёты, платежи и загрузка данных недоступны. После смены туннеля публикация настроек на GitHub Pages может занять несколько минут.

## Службы

Отдельный префикс `md.numerom.app.`: `api`, `gateway`, `tunnel`, `watchdog`, `awake`. API и шлюз слушают только loopback 8000/8004. Туннель ведёт только к ограниченному публичному шлюзу. Службы Helper не изменяются.

Управление из корня проекта:

```sh
./backend/.venv/bin/python scripts/numerom_services.py status
./backend/.venv/bin/python scripts/numerom_services.py install
./backend/.venv/bin/python scripts/numerom_services.py restart api
```

Сторож запускается раз в минуту. После трёх неудачных проверок перезапускается соответствующая служба. Новый публичный адрес сначала проверяется через `/api/health`, затем сохраняется в приватных настройках сервера и подписывается. В публичный репозиторий попадает только `runtime-config.json`. Подтверждение его появления на Pages хранится отдельно от успешного отправления в GitHub. Публикация полной сборки и сторож используют один файловый замок.

MongoDB `numerom_mongodb` использует существующую политику Docker `unless-stopped`. Docker Desktop должен работать; явно остановленный контейнер эта политика намеренно не запускает.

## Доверие и повторные запросы

`mobile/src/lib/endpointTrust.json` содержит только открытый ключ. Приложение проверяет подпись ECDSA P-256 с SHA-256, HTTPS-адрес и версию настроек, отклоняет подмену и откат относительно уже проверенного файла. Проверка работает без WebCrypto, в том числе в React Native; используется [noble-curves](https://github.com/paulmillr/noble-curves/tree/1.9.7).

Закрытый ключ находится в `backend/private/runtime/endpoint-signing.pem`, доступен только владельцу (0600), исключён из Git и публикации. Его следует сохранять вместе с приватной резервной копией сервера. Потеря ключа не приводит к молчаливому созданию другого: старые приложения доверяют прежнему ключу.

При смене адреса автоматически повторяются только GET-запросы и только один раз. Оплаты, расчёты, регистрации и загрузки не повторяются после неоднозначного ответа. Существующий механизм идентификатора попытки сохраняется. Ошибка сети не удаляет сохранённый вход. Запросы имеют срок ожидания, включая случай, когда транспорт не завершился после отмены.

## Проверка

Артефакты текущего запуска: `artifacts/server-recovery-20261022/`. Фактические результаты перезапуска, смены адреса, публикации и повторного подключения сохраняются после выполнения проверок; наличие исходного кода само по себе не подтверждает живое восстановление.
