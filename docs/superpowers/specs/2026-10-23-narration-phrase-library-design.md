# Банк озвученных фраз для полного разбора

Дата: 23.10.2026. Статус: дизайн одобрен владельцем.

## Цель

Озвучивать новый полный разбор в 3–5 раз быстрее, переиспользуя уже озвученные и проверенные предложения. Качество озвучки, проверка произношения и синхронизация видео не ухудшаются.

## Замер

Отчёты для 12 разных дат рождения (без текста Ollama), разбитые на предложения так, как их произносит обработчик:

| Отчёт | Уже озвучено ранее |
|---|---|
| 2-й | 63% знаков |
| 3–7-й | 73–84% |
| 8–12-й | 81–86% |

Библиотека после 12 дат: 1674 предложения, 109 тыс. знаков, дальше растёт медленно. Личный текст Ollama (смысловой разбор, практики) уникален и составляет примерно 20–25% отчёта.

## Решение

### 1. Банк фраз

- Единица — одно предложение после `spoken()` (числа словами, латинские буквы по-русски), разбитое функцией `sentences()`; обрывки короче трёх слов присоединяются к соседу.
- Ключ: `sha256([текст, профиль голоса, MODEL, sha256 эталона])`. Новый эталон или настройки голоса автоматически дают новый банк.
- Хранение: `backend/private/narration/phrases/<ключ[:2]>/<ключ>.wav` и `.json` (`text`, `heard`, `difference`, `seconds`, `cues`, `generation`, `created_at`). Запись атомарная, права 0600.
- В банк попадают только фразы с расхождением не больше 7%. Фраза считается найденной, только если есть и WAV, и JSON с совпадающим `text`.

### 2. Сборка главы в обработчике `generate-project-voices.py`

1. Текст главы → `segments()` → `sentences()` → список фраз в порядке чтения.
2. Найденные в банке фразы не синтезируются и не проверяются повторно.
3. Недостающие — пачкой: модель синтеза загружается один раз на все фразы главы, после синтеза выгружается; затем Whisper один раз проверяет все. Две модели одновременно в памяти не находятся (как в режиме `--low-memory`).
4. Не прошедшие проверку фразы — следующий раунд с новыми сидами (`generation_seed`), не больше трёх раундов. Если фраза не прошла, глава получает `failed.json` и статус «на проверке», лучшая попытка сохраняется в `review-*.wav/json`, как сейчас.
5. Склейка: фразы через паузу `GAP = 0.38` с (как в `domain/report_video.py`). Для голоса Дмитрия — `loudness()` на всю главу.
6. `ready.json`: `segments` — по одной записи на фразу (`text`, `heard`, `difference`, `seconds`, `cues`, `generation`, `phrase`). Видео принимает это без изменений: равная пауза 0,38 с и не больше 256 записей в главе. Если фраз больше 256, соседние фразы одного сегмента объединяются в одну запись: её `seconds` включает внутренние паузы, а `cues` сдвинуты на позицию каждой фразы.

Запасной путь «по предложениям» и кэш сегментов `{index}-{chunkhash}.wav` становятся не нужны для новых глав; готовые главы не перегенерируются.

### 3. Прогрев

- Скрипт `scripts/prepare-phrase-warmup.py` строит `build_full_report()` для синтетических дат (без профилей клиентов и без Ollama), извлекает фразы и пишет недостающие в очередь прогрева `backend/private/narration/warmup/*.json`.
- Даты добавляются, пока очередная дата приносит больше 1% новых фраз. Ожидаемо 1700–2500 фраз, около 5–6 часов работы один раз.
- Обработчик берёт прогрев, только когда нет ни одного задания на озвучку, пачками по 20 фраз в общем слоте генерации; затем снова проверяет очередь. Настоящий заказ ждёт не дольше одной пачки (около 2–3 минут).
- Данные клиентов в прогрев не попадают никогда.

### 4. Без изменений

Готовые главы и видео, порядок очереди, порог проверки 7%, сравнение (`comparison_words`), повтор неудачных глав через `retry_report`, голос Helper для старых заданий.

## Ошибки и восстановление

- Повреждённая фраза банка (нет WAV или JSON, другой текст) считается отсутствующей и озвучивается заново.
- Падение процесса между синтезом и проверкой: непроверенные фразы в банк не записаны, повторный запуск их пересоздаёт.
- `generation.json` хранит сиды и расхождения по фразам для диагностики.

## Проверка

Тесты без модели (фальшивые синтез и Whisper):
- найденная фраза не вызывает синтез и Whisper;
- фазы идут пачкой: все синтезы, затем все проверки;
- неудачная фраза повторяется с новым сидом, после трёх раундов глава уходит на проверку;
- `ready.json` проходит `build_manifest()` (сумма длительностей + паузы 0,38 с);
- прогрев запускается только при пустой основной очереди и только из синтетических дат.

Живая проверка: одна глава озвучивается целиком; вторая глава с общими фразами собирается без вызова синтеза; прослушивание образца владельцем.
