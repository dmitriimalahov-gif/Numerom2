# NumerOM: рефакторинг и мобильное приложение

Подтверждено пользователем: светлый, спокойный современный дизайн; авторские PNG; iPhone и Android, общие аккаунты и данные сайта. Пользователь поручил составить план и сразу начать реализацию.

## Архитектура

Работающий backend/server.py остаётся точкой запуска. Домены постепенно извлекаются в backend/domain, backend/services и backend/routers, с передачей базы через зависимости и сохранением HTTP-контрактов. backend_clean, deploy, numerom-v0 и numerom-v2 не являются источником новой реализации. MongoDB, пользователи, баллы, уроки и расчёты общие для клиентов.

packages/api-client — независимый от React пакет: адреса, запросы, ошибки, контракты, восстановление сессии. frontend остаётся CRA/React 19; переезд сборщика не смешивается с переносом логики. mobile — отдельное приложение Expo, React Native, TypeScript, Expo Router. Нативное хранение токена — SecureStore. Мобильные компоненты используют спокойную палитру NumerOM и исходные PNG.

## Первый исполняемый этап

1. Общий API-клиент с таймаутом, отменой, корректным Bearer и различением 401/сети; сайт использует общий resolver адреса и общий профильный клиент.
2. Извлечение login и profile-v2 GET/PATCH из действующего сервера, защита редактируемых полей, безопасный ответ профиля и удаление логов секретов. Регистрация и расчёты пока сохраняют существующие серверные маршруты.
3. Мобильные экраны: вход/регистрация, восстановление сессии, обзор, персональные числа, список и карточка урока, библиотека PNG, редактирование профиля и выход. У каждой загрузки есть ожидание, пустой результат и ошибка с повтором. Числа поступают из API; учебные PNG не выдаются за персональные результаты. Мутации не повторяются автоматически. Стоимость расчёта показывается перед действием по серверной конфигурации.
4. Тесты контрактов/сессии, web build, mobile typecheck/doctor/экспорт iOS и Android. Нативная сборка и тест телефона отмечаются отдельно; без подписи не заявлять публикацию.

## План полного переноса

| Очередь | Область | Критерий завершения |
|---|---|---|
| 1 | Основа и мобильный вертикальный срез | Критерии первого этапа выше |
| 2 | Расчёты, баллы, история | Доменные сервисы и API; параллельные списания/отмена/повтор проверены на Mongo; все виды расчётов доступны обоим клиентам |
| 3 | Обучение | Убраны дубли маршрутов; доступы, прогресс, тесты и упражнения совместимы; медиа, PDF и прерывание просмотра проверены на устройствах |
| 4 | Консультации, отчёты, платежи | Раздельные сервисы; webhook idempotency; реальные Stripe TEST-сценарии; нативная стратегия покупок согласована до магазинов |
| 5 | Администрирование и web UI | AdminPanel, LearningSystemV2, ComprehensiveReport разбиты по функциям; сохранены права и сценарии; доступность и адаптивность проверены |
| 6 | Выпуск | Настройки секретов и CORS, CI, резервное копирование/откат; iOS/Android development builds, device QA, подпись, store assets и политика данных |

Каждый следующий этап требует конкретизации по реальным контрактам, а не механического разбиения строк. Полный рефакторинг не считается завершённым после одного вертикального среза.

## Ограничения

Сохранить незакоммиченный редизайн и исходные материалы. Не мигрировать/стирать production данные, не перезапускать чужие процессы, не публиковать, не менять TEST на LIVE. Не переносить фиктивные данные в основной режим приложения. Не использовать реальные учётные записи в автоматических тестах. Доступ к отсутствующему API показывать честно, а не подставлять успех. Существующий механизм подписки, расчёт баллов и обучение не переписывать без контрактных тестов.
