# Оплата и баллы NumerOM

Актуальная реализация: `backend/domain/payments.py`, `backend/services/payments.py`, `backend/routers/payments.py`.
Мобильный интерфейс: `/top-up`, возврат Stripe: `/payment-result/`. На основном сайте используются PaymentModal и `/payment-success`.

## Пакеты

| Пакет | EUR | Баллы | Дополнение |
|---|---:|---:|---|
| Стартовый | 0,99 | 10 | 30 дней доступа |
| Месяц практики | 9,99 | 150 | 30 дней доступа |
| Год практики | 66,60 | 1000 | 365 дней доступа |
| Консультация мастера | 666,00 | 10000 | Назначение персональной консультации |

Это **разовые оплаты без автоматического продления**. Сервер задаёт цену и количество баллов. Старые примеры demo-начислений и рекуррентных подписок больше не описывают работающую систему.

## Подтверждение

1. Авторизованный клиент выбирает пакет и сохраняет UUID попытки до запроса.
2. Сервер сохраняет заказ и создаёт Stripe Checkout Session с постоянным idempotency key. Повтор запроса возвращает ту же оплату.
3. Stripe отправляет подписанное уведомление на `POST /api/webhook/stripe`. Шлюз сохраняет исходные байты и заголовок `Stripe-Signature`.
4. Сервер проверяет подпись, получает текущий Checkout Session из Stripe и сверяет заказ, владельца, валюту, сумму, пакет и режим.
5. Только `payment_status=paid` позволяет начисление. Баланс и маркер оплаченного заказа изменяются одной атомарной операцией MongoDB. История доставляется через сохраняемую очередь.
6. Страница возврата проверяет статус на сервере. Параметры URL сами по себе не означают успешную оплату. При потерянном ответе доступны продолжение, повторная проверка и отмена незавершённой сессии.

Обрабатываются `checkout.session.completed`, `checkout.session.async_payment_succeeded`, `checkout.session.async_payment_failed`, `checkout.session.expired`. Позднее уведомление не отменяет уже подтверждённую оплату. Для просмотра и отмены требуется владелец заказа.

## Локальная конфигурация

Все секреты находятся только в закрытом `backend/.env` (права 0600), исключённом из Git и Docker context. Не вводить ключи в чат или клиентский код.

- `STRIPE_SECRET_KEY`: секретный или ограниченный серверный ключ соответствующего режима.
- `STRIPE_WEBHOOK_SECRET`: секрет зарегистрированного webhook.
- `STRIPE_MODE`: `test` или `live`.
- `STRIPE_SANDBOX_EXPIRES_AT`: дата истечения временной sandbox; после неё новый checkout автоматически отключён. Удаляется или заменяется при подключении постоянной тестовой среды.
- `STRIPE_MOBILE_RETURN_URL`: фиксированный HTTPS-адрес мобильного возврата.
- `STRIPE_WEB_RETURN_URL`: фиксированный адрес возврата основного сайта. HTTP localhost разрешён только для тестов.
- `STRIPE_LIVE_ENABLED=1`: отдельный явный переключатель для LIVE после активации аккаунта владельцем.

Отсутствие настроек отключает checkout. Секреты нельзя заменять demo-значениями. После смены публичного API-адреса watchdog автоматически переносит существующий тестовый webhook. При ошибке Stripe перенос повторяется на следующем цикле, а восстановление приложения продолжается. Секрет подписи сохраняется; LIVE этот механизм не изменяет. Состояние доступно в `backend/private/runtime/watchdog-state.json`, поле `stripe_webhook`.

Тестовая оплата подключается запуском `Подключить Stripe (тест).command` (`scripts/stripe_test_environment.py`). Enter без ключа повторяет настройку 16.10.2026: Stripe CLI создаёт временную sandbox на 7 дней (`stripe --project-name numerom-credits sandbox create --non-interactive`), ключ ниоткуда вводить не нужно; ссылка «закрепить» делает её постоянной. Вместо Enter можно вставить постоянный ключ `sk_test_…`. Затем webhook регистрируется на текущий `PUBLIC_API_URL`, ключ и секрет пишутся только в `.env` активного runtime, срок sandbox — в `STRIPE_SANDBOX_EXPIRES_AT`, API перезапускается. Повторный запуск с тем же ключом переносит существующий webhook на новый адрес туннеля. Публичная мобильная сборка содержит только интерфейс и адрес шлюза.

## Текущий тестовый стенд

7 ноября 2026 восстановлена отдельная временная Stripe sandbox; она истекает **14 ноября 2026** без подтверждения владельцем. Причины сбоя: прежний ключ вернул `api_key_expired`, webhook оставался на старом адресе туннеля. Ссылка подтверждения и CLI-конфигурация находятся в игнорируемой закрытой папке `backend/private/stripe`. LIVE не включён.

Тестовые покупки начисляются только в `test_credits_remaining`; они не увеличивают рабочий баланс, не продлевают доступ и не назначают реальные консультации. На экране явно указан тестовый режим. В браузере проведена настоящая тестовая Checkout-оплата 0,99 EUR стандартной картой Stripe. Webhook самостоятельно выдал 10 тестовых баллов до входа в приложение; рабочие 13 остались без изменения. Пять повторных проверок не увеличили баланс, запись начисления одна. Мобильная страница возврата показала подтверждение и тестовый баланс. Создание отдельной тестовой оплаты полного разбора на 6,66 EUR также проверено; эта неоплаченная сессия закрыта. Артефакты проверки: `artifacts/stripe-test-repair-2026-11-07/`.

После замены временной среды просроченная тестовая попытка, для которой Stripe отвечает `resource_missing`, получает статус `expired` и позволяет клиенту очистить сохранённую попытку. Сетевые ошибки, ещё действующие сессии, уже оплаченные заказы и LIVE этим правилом не закрываются. Проверены 81 целевой тест, включая параллельное начисление, подпись webhook, полный разбор и восстановление адреса.

## Консультации после покупки

Мобильный экран `/consultations` показывает только активные консультации, назначенные текущему пользователю. Для пакета мастера в LIVE создаётся назначение с бесплатным доступом к его материалам; пока мастер не добавил файлы, отображается «Материалы готовятся».

Отдельные назначенные консультации можно открыть за рабочие баллы с явным подтверждением цены. Списание и право доступа записываются атомарно; сайт и мобильный клиент используют общий маркер покупки. Повторное нажатие не списывает баллы повторно. При изменении цены запрос отклоняется до списания.

PDF и видео открываются по короткоживущим ссылкам с повторной проверкой назначения, покупки, блокировки и версии авторизации. Файлы поддерживают Range и `no-store`. Сторонние видеоссылки открываются отдельно после проверки доступа; их защиту обеспечивает внешний видеохостинг.

## Границы готовности

Проверены локальные тесты, реальная Stripe sandbox и публичная браузерная версия. Реальные списания, возвраты, споры, LIVE-аккаунт и выплаты не проверены. Автоматическая обработка возвратов/споров пока не реализована. До LIVE требуется отдельный порядок корректировки баллов при возврате.

API пилота работает на Mac через временный туннель; для постоянной эксплуатации нужны стабильный сервер и домен. Нативные IPA/APK не опубликованы и магазинные платежи не заявлены: правила цифровых покупок для App Store/Google Play требуют отдельной проверки перед выпуском.
